# ADR-005: 한영 명칭 매핑에 7단계 방어선 적용, 퍼지 매칭 전면 금지

- 상태: 채택 (2026-09-22)
- 관련: Phase 2, `app/ingestion/`, `backend/data/name_map.json`, `CLAUDE.md` 8-4, `DEVELOPMENT_GUIDE` 4-5
- 기록: 소급 작성 (2026-11-03). PokéAPI 실측 조사는 이 날짜에 수행했다.

## 맥락

데이터는 영문으로 들어오고(`Garchomp`, `Earthquake`, `Choice Scarf`) 사용자는 한국 서버
표기(`한카리아스`, `지진`, `구애스카프`)로 읽는다. 그 사이를 잇는 매핑이 필요하다.

**이 구간이 위험한 이유는 틀렸을 때 조용하기 때문이다.** 데미지 계산이 틀리면 수치가 이상해서
눈에 띈다. 그런데 이름 매핑이 틀리면 화면에는 멀쩡한 한글 이름이 뜨고, 그 뒤에서 엉뚱한
포켓몬의 종족값으로 계산이 돌아간다. 사용자도 모르고 우리도 모른다. 추천 전체가 조용히 무너진다.

이 서비스는 "모든 출력에 근거를 붙인다"가 존재 이유인데, 근거의 대상이 틀리면 그 전제가 깨진다.
따라서 이 구간만은 **오류 허용치를 0으로 잡아야 했다.**

한국어 명칭의 출처로는 PokéAPI를 쓴다. 정적 참조 데이터이고 ID로 조회되며,
[ADR-002](002-data-source.md)의 battle data API 약관과 무관한 별개 소스다.

## 선택지

### A안: 단일 방어 — 매핑 테이블 하나 + 실패 시 로깅
- 장점: 구현이 단순하고 빠르다.
- 단점: 매핑이 틀렸는지 알 방법이 없다. 로깅은 "실패"만 잡지 "조용히 잘못 붙은 것"은 못 잡는다.

### B안: 퍼지 매칭으로 커버리지 확보
- 장점: 미매핑이 거의 사라진다. 신규 항목도 자동으로 붙는다. 운영 부담이 적다.
- 단점:
  - **틀려도 에러가 안 난다.** 임계값을 넘는 엉뚱한 후보가 조용히 반환된다.
  - 실패가 로그에도 안 남아 사람이 개입할 계기가 없다.
  - 이 도메인의 실패 양상(잘못된 포켓몬으로 계산)과 최악의 궁합이다.

### C안: 다층 방어선 — 정확 일치만 허용하고 여러 단계로 교차 검증
```
1. ID 조인          (문자열 비교 없음)
2. 종족값 교차검증   (자동, 가장 강력)
3. 양방향 유일성     (자동)
4. 커버리지 테스트   (CI — 미매핑 하나면 빌드 실패)
5. 골든 동결        (회귀 방지)
6. 사람 검수        (초기 1회 + 시즌 전환)
7. Fail-closed     (뚫려도 서비스에 반영 안 됨)
```
- 장점:
  - 하나가 뚫려도 다음이 잡는다. 특히 2단계는 사람 눈보다 정확하다 —
    매핑이 틀리면 종족값이 거의 확실히 달라진다.
  - 실패가 **시끄럽다.** 빌드가 깨지거나 스냅샷이 비활성 상태로 남아 반드시 사람이 본다.
- 단점:
  - 구현량이 많다. 검증기·커버리지 테스트·골든 픽스처·pending 큐를 전부 만들어야 한다.
  - 6단계(사람 검수)가 반복 비용으로 남는다.
  - 신규 항목이 나올 때마다 빌드가 깨져 수동 개입이 필요하다 — 의도한 동작이지만 운영 마찰이다.

## 결정

**C안(7단계 방어선)을 채택하고, 퍼지 매칭을 전면 금지한다.**

- 레벤슈타인 거리·유사도 임계값·"가장 비슷한 것 고르기" 구현은 리뷰에서 반려한다.
- 매핑 실패 시 fail-closed — 영문명을 통과시키거나 추측하거나 항목만 건너뛰지 않는다.
  스냅샷을 활성화하지 않고 `name_map_pending.json` 에 원문 그대로 적재한 뒤 보고한다.
- `name_map.json` 은 커밋해서 고정한다. 런타임에 PokéAPI를 호출하지 않는다.
- 폼 명칭은 패턴을 런타임 조합하지 않고 **검수된 확정 문자열만** 넣는다.

**설계 철학**: 실수 가능성을 0으로 만드는 문제가 아니라, **실수가 사용자에게 도달하지 못하게
막는** 문제로 접근한다.

## 근거

(2026-11-03, 개발자 본인 기록)

**왜 이 구간에만 방어선을 두껍게 쳤는가**
영문 데이터를 가져오지만 실제 서비스 타깃은 한글을 쓰는 사람이다.
본인도 포켓몬 관련 영문 자료를 LLM에 해석을 맡겼을 때 **포켓몬 이름을 다르게 말해서 혼동이
간 적이 있고, 그래서 파티를 짤 때 많이 불편했던 기억**이 있다. 그 경험이 근거다.

**퍼지 매칭 금지는 누구의 판단이었는가**
퍼지 매칭이 무엇인지 기억나지 않는다고 답했다. 본인이 그 개념을 알고 내린 판단이 아니며,
설계 초안에 있던 것을 유지한 것이다. (개념 설명은 2026-11-03 대화에서 처음 받았다.)

**사람 검수(6단계)를 수행할 수 있는가**
가능하면 기존 한글-영어 매핑 데이터를 쓰고 싶고, 불가능하면 어쩔 수 없이 사람이 검수한다.
→ 조사 결과 본체 이름은 PokéAPI로 자동화 가능, 폼은 불가능으로 확인됐다. 아래 참고 절 참조.

**영문 데이터와 한국어 명칭의 출처가 분리된 것은 의도였는가**
의도한 설계가 아니라 결과적으로 그렇게 된 것이다.

## 포기한 것

- **커버리지의 편의.** 신규 포켓몬·기술이 추가될 때마다 빌드가 깨지고 수동 개입이 필요하다.
  퍼지 매칭이었다면 자동으로 넘어갔을 일이다. **이 마찰을 의도적으로 감수한다** —
  조용히 틀리느니 시끄럽게 멈추는 쪽을 택했다.
- **구현 속도.** 검증기 5종, 커버리지 테스트, 골든 픽스처, pending 큐, 검수 스크립트를
  전부 만들어야 한다. Phase 2의 상당 부분이 여기 들어간다.
- **신규 데이터의 즉시 반영.** 미매핑 항목이 하나라도 있으면 스냅샷 전체가 비활성 상태로 남는다.
  메타 갱신이 사람의 개입을 기다려 늦어질 수 있다.
- **완전 자동화.** 폼 명칭만큼은 사람 손을 뺄 수 없다 (아래 참고 절).

## 되돌리는 조건

- **운영 마찰이 감당 불가**: 시즌마다 미매핑으로 메타 갱신이 장기간 멈추면,
  퍼지 매칭을 허용하는 게 아니라 **pending 큐 처리 UX를 개선**하는 쪽으로 푼다.
  방어선 완화는 마지막 수단이다.
- **종족값 교차검증 무력화**: 챔피언스가 종족값을 조정해 본가와 달라지면 2단계가 작동하지 않는다.
  그 경우 검증 기준을 타입·특성 조합 등으로 바꾼다. **검증을 없애지 않는다.**
- **PokéAPI 표기와 한국 서버 표기의 체계적 불일치 발견**: 샘플 검증에서 다수 불일치가 나오면
  한국어 명칭 출처 자체를 재검토한다.

## 참고 — PokéAPI 한국어 명칭 실측 조사 (2026-11-03)

**본체 이름: 12/12 정확.** 한국 서버 표기와 일치했다.

| 분류 | 확인 항목 |
|---|---|
| 포켓몬 | 한카리아스 · 마기라스 · 마스카나 |
| 기술 | 지진 · 스케일샷 · 스텔스록 |
| 도구 | 구애스카프 · 돌격조끼 · 먹다남은음식 |
| 특성 | 까칠한피부 · 불가사의부적 · 다운로드 |

**폼: 자동 생성 불가.**

| 폼 | `names.ko` | `form_names.ko` |
|---|---|---|
| garchomp-mega | 없음 | 메가한카리아스 ← 완성된 이름 |
| raichu-alola | 없음 | 알로라의 모습 ← 수식어구 |
| lycanroc-midnight | 없음 | 한밤중의 모습 ← 수식어구 |
| urshifu-rapid-strike | 없음 | 연격의 태세 ← 수식어구 |
| basculegion-female | 없음 | 없음 |
| tauros-paldea-aqua | 없음 | 없음 |

`names.ko` 는 6건 전부 비어 있고, `form_names.ko` 는 **형식이 일관되지 않는다.**
완성된 이름과 수식어구가 섞여 있어 `수식어 + 본체명` 조합으로는 한국 서버 표기를 만들 수 없다.
2건은 데이터 자체가 없다.

**→ 6단계(사람 검수)의 범위를 재정의한다.**

| 대상 | 방법 | 사람 손 |
|---|---|---|
| 포켓몬 본체 | PokéAPI + 종족값 교차검증 | 불필요 (기계가 더 정확) |
| 기술 | PokéAPI + 타입·위력·분류 검증 | 불필요 |
| 도구·특성 | PokéAPI (숫자 검증 불가) | 샘플 점검 |
| **폼** | **수동 확정 문자열** | **필수** |
| 챔피언스 전용 항목 | PokéAPI에 없음 → fail-closed | 필수 |

"상위 50마리 전수 검수"에서 **"챔피언스 랭킹에 등장하는 폼 + 검증 실패분"** 으로 범위가 줄어든다.
시즌 전환 시에도 신규 폼만 확인하면 된다.
