# ADR-009: 기술 마스터 수치를 op.gg 챔피언스 표에서 생성, 본가 데이터 전면 배제

- 상태: 채택 (2026-11-08)
- 관련: Phase 2-2, `backend/scripts/generate_moves.py`, `backend/data/moves.json`,
  `backend/data/name_map_moves.json`, `app/domain/movedex.py`, `CLAUDE.md` 8-3 / 8-5
- 관련 결정: [ADR-002](002-data-source.md) (사용률 출처), [ADR-005](005-name-mapping-defense.md) (한영 매핑)

## 맥락

데미지 계산에는 기술의 위력·타입·분류가 필요하다. championsbattledata 공개 API는
채용률만 주고 기술 수치는 주지 않는다. `CLAUDE.md` 8-3이 이 공백을 예상하고
"기술 위력·명중·PP·플래그는 API가 제공하지 않으므로 `backend/data/moves.json`에
직접 관리한다"고 적어뒀다. 그 파일을 무엇으로 채울지가 이 결정이다.

Phase 2-1에서 **챔피언스 종족값이 본가와 같다**는 것을 PokéAPI 대조로 확인했다.
그래서 기술도 같을 것이라 기대할 만했다. **그 기대가 틀렸다.**

| 기술 | 본가 | 챔피언스 |
|---|---|---|
| 부리캐논 | 위력 100 | 위력 **120** |
| 스타어설트 | 위력 150 | 위력 **170** |
| 배리어러시 | 위력 70 | 위력 **90** |
| 10만볼트 | PP 15 | PP **16** |
| 강철날개 | PP 25 | PP **20** |
| 드래곤클로 | (베기 아님) | **베기** 기술로 재분류 |

챔피언스는 별개 엔진이고 밸런스 패치로 기술을 계속 조정한다. PP는 본가의 5~40
제각각에서 **{1, 8, 12, 16, 20} 다섯 값으로 정규화**됐다. 2026-04-08 출시 패치,
06-17, 09-09 패치에서 위력·명중이 바뀌었고, '베어가르기'는 신규 추가됐다.

**이 틀림의 양상이 위험하다.** 위력이 100인지 120인지는 화면에서 이상해 보이지 않는다.
확정 1타가 난수 1타로 뒤바뀌고, 사용자는 그 수치를 근거로 선출을 결정한다.
ADR-005가 한영 매핑에 대해 지적한 "조용한 실패"와 같은 구조다.

종족값을 실수치로 착각했던 직전 사건(Phase 2-1)과도 같은 종류다. **출처가 주는 숫자가
무엇인지 확인하지 않고 쓰면 틀린다.**

### op.gg의 데이터 사용 조건 (2026-11-08 확인)

처음에는 op.gg에 명시적 데이터 정책이 없다고 판단했으나, 헬프센터에 공식 입장이 있었다
([OP.GG 데이터를 사용해도 되나요?](https://help.op.gg/hc/ko/articles/31091405109401), 2025-12-31 갱신):

> **Q. OP.GG의 데이터를 크롤링하여 사용해도 되나요?**
>
> 일반적으로 OP.GG에서 제공하는 데이터의 크롤링이나 웹 스크래핑을 금지하고 있지는 않습니다.
> 다만, 출처를 명시하지 않은 상업적 활용이나 과도한 요청으로 서비스 운영에 영향을 주는
> 경우에는 서비스 접근이 제한될 수 있습니다.
>
> 데이터를 활용할 경우 출처 표기를 준수하고, 서비스 운영에 영향을 미치지 않도록 유의해
> 주시기 바랍니다.

즉 **금지가 아니라 조건부 허용**이고, 조건이 두 개다.

| 조건 | 이 프로젝트의 상태 |
|---|---|
| 출처를 명시하지 않은 상업적 활용 금지 | 비영리 개인 프로젝트 + 출처 표기 (결정 6항) |
| 과도한 요청으로 운영에 영향 금지 | 생성기 실행당 **페이지 1회 요청**, 런타임 호출 없음 |

`robots.txt` 역시 `User-Agent: * / Allow: /` 다.

이 확인이 선택을 바꾼 건 아니지만 **트레이드오프의 크기를 바꿨다.** 처음 판단한
"허가 없이 파싱한다"가 아니라 "명시된 조건을 지키며 파싱한다"가 된다.
그래서 출처 표기는 품질 항목이 아니라 **사용 조건**이다.

## 선택지

### A안: 공개 커뮤니티 데이터셋 사용 (`vbbjandrade/pokemon-champions-data` 등)
- 장점:
  - CC-BY 4.0. 상업적 사용과 재배포가 명시적으로 허용된다. 라이선스 리스크가 가장 작다.
  - 구조화된 JSON. 파서를 쓸 필요가 없다.
  - learnset·특성·도구까지 한 번에 들어온다.
- 단점:
  - **내용이 챔피언스가 아니다.** 저장소 이름만 Champions이고 `sources` 필드가
    `["smogon/pokemon-showdown"]`을 가리킨다. 부리캐논 100, 강철날개 PP 25, 기술 954개
    (챔피언스는 515개), 드래곤클로에 베기 플래그 없음.
  - 더 오래된 `otterlyclueless` 쪽은 2026-04 이후 갱신이 없어 패치가 전혀 반영돼 있지 않다.
  - 라이선스가 깨끗한 대신 **데이터가 틀렸다.** 이 프로젝트에서는 가장 나쁜 조합이다.

### B안: 본가 데이터(PokéAPI) + 패치 차이만 수동 오버라이드
- 장점:
  - 출처가 공식에 가깝고 안정적이다. 필드가 완비돼 있다.
  - 오버라이드 목록 자체가 패치 이력 문서가 된다.
- 단점:
  - **오버라이드 목록이 완전한지 확인할 방법이 없다.** 패치노트는 나무위키 등 팬 자료뿐이고,
    누락되면 조용히 본가 값이 남는다. "어디가 다른지 모른다"가 위험의 본질이다.
  - PP가 전면 재조정됐고 515개 중 어디가 바뀌었는지 패치노트에 다 없다.
  - 기술 집합 자체가 다르다(954 vs 515). 챔피언스에 없는 기술이 섞여 들어온다.

### C안: op.gg 챔피언스 기술 표에서 시드를 생성
- 장점:
  - **패치가 반영된 유일한 기계판독 출처다.** 위력·명중·PP·우선도·플래그·타깃을 모두 제공한다.
  - 기술 집합이 챔피언스 그대로다(515개). 본가 전용 기술이 섞이지 않는다.
  - 한글명이 함께 들어 있어 ADR-005의 매핑 작업에 바로 쓰인다.
  - 영문 slug를 쓰므로 사용률 API의 영문 표시명과 ID 조인이 된다(실측 확인).
- 단점:
  - **상업 사이트의 HTML을 파싱한다.** 데이터 라이선스 문서(CC-BY 같은 것)는 없고,
    헬프센터의 조건부 허용 입장이 전부다. 그 입장은 언제든 바뀔 수 있다.
    → 조건을 지키는 책임이 우리에게 남는다 (출처 표기, 요청량).
  - 표 구조가 바뀌면 파서가 깨진다. 분류(물리/특수/변화)가 텍스트가 아니라 아이콘이라
    svg 파일명에 의존한다.
  - `CLAUDE.md` 8-5가 "op.gg 스크래핑은 Phase 2 범위에서 제외"라고 적고 있어 문서와 충돌한다.
  - 단일 출처다. 그 사이트가 틀리면 우리도 틀린다.

### D안: 상위 사용률 기술만 수동 큐레이션
- 장점: 외부 의존이 없고 전수가 검수된다. 라이선스 문제가 사라진다.
- 단점:
  - 사용률 상위만 담으면 **범위 밖 기술을 만났을 때 계산이 불가능**해진다. 사용자가 쓰는 건
    메타 기술만이 아니다.
  - 515개를 손으로 넣으면 오타가 들어온다. 오타의 양상이 또 조용하다.
  - 패치마다 사람이 전수 재검수해야 한다.

## 결정

**C안(op.gg에서 시드 생성)을 채택하고, 본가 파생 데이터는 전면 배제한다.**

세부 사항:

1. **런타임 수집이 아니다.** 생성기를 사람이 돌려 `data/moves.json`을 커밋한다.
   서비스 요청 경로는 op.gg를 호출하지 않고, `ingestion/`의 `StatsSource` 구현체로도
   만들지 않는다. 밸런스 패치가 나올 때만 다시 돌린다.
   → `CLAUDE.md` 8-5의 "op.gg 스크래핑 제외"는 **사용률 수집**에 대한 조항으로 읽고,
     기술 마스터는 8-3이 규정한 "직접 관리하는 시드 데이터"로 분류한다.
2. **단일 출처의 위험을 교차검증으로 덮는다.** 생성기가 매번 세 출처를 대조한다.
   - champions-helper `/data/moves.json` — 출시 패치 **전** 스냅샷. 위력 15건·명중 3건이
     다르고 **그 18건이 전부 알려진 패치 목록과 일치한다.** `EXPECTED_*_DIFFS`로 고정하고
     **목록 밖 차이가 하나라도 생기면 생성을 중단한다.**
   - smartnuo `/api/move` — 기술 한글명 892개.
   - championsbattledata 사용률 API — 263종 전수 조인. 해석 안 되는 기술이 하나라도
     있으면 중단한다.
3. **매핑은 검수된 확정 문자열만.** 타입 18·플래그 13·타깃 15를 전수 열거해 사전으로
   고정했다. op.gg가 값을 하나라도 추가하면 생성이 실패한다. 퍼지 매칭은 없다(ADR-005).
4. **한글명은 `moves.json`에 담지 않는다.** `name_map_moves.json`으로 분리한다(ADR-005).
5. **요청 간 1초 지연, 동시성 1** (`CLAUDE.md` 8-6).
6. **출처 표기는 사용 조건이다.** 기술 수치가 표시되는 모든 화면에 op.gg를 출처로
   표기하고 링크한다. `CLAUDE.md` 8-2가 championsbattledata에 요구하는 것과 같은 수준으로
   다룬다 — 푸터 한 줄로 끝내지 않는다. Phase 2-7의 출처 표기 컴포넌트에 포함한다.
   이 표기가 빠지면 op.gg 정책의 제한 조건("출처를 명시하지 않은 상업적 활용")에
   가까워지므로, **구현 전까지 기술 수치를 외부에 공개하지 않는다.**
7. **수익화하지 않는다.** 이 결정의 근거가 비영리 개인 프로젝트라는 전제에 서 있다.
   전제가 바뀌면 결정을 다시 한다 (아래 되돌리는 조건).

## 근거

> 기존 본가 배틀에서 사용됐던 데이터들이 포켓몬 챔피언스에서 소량 변경된 점이 있고
> 이 변경사항이 있는 한 서비스에서는 정확한 데이터를 사용해야 하기 때문에
> 포켓몬 챔피언스에 특화된 op.gg에서 사용했으며,
> 출처를 표기하지 않은 상업적 사용이 아닌 서비스 배포 경험을 쌓기 위한 개인프로젝트로써
> 출처를 명확히 하고 수익을 창출하려는 활동이 아니라서 이렇게 결정

(참고 링크로 [OP.GG 데이터 사용 정책](https://help.op.gg/hc/ko/articles/31091405109401)을 제시함.
위 "출처를 표기하지 않은 상업적 사용이 아닌"은 그 문서의 제한 조건을 그대로 짚은 것이다.)

## 포기한 것

- **문서화된 라이선스.** A안을 택했다면 CC-BY 4.0이라는 재배포까지 허용된 명문 라이선스가
  있었다. 지금 근거는 헬프센터의 조건부 허용 입장 하나이고, 그건 약관이 아니라 FAQ다.
  op.gg가 입장을 바꾸면 우리 쪽에 구제 수단이 없다.
- **상업화 경로.** 근거가 "비영리 개인 프로젝트"에 서 있으므로, 수익화를 하려면
  이 결정부터 다시 해야 한다. 지금 선택이 미래의 선택지를 좁혔다는 점을 명시해 둔다.
- **파서 안정성.** op.gg가 표 구조나 아이콘 경로를 바꾸면 생성기가 깨진다.
  다만 깨질 때 **조용히 틀리지 않고 멈춘다** — 그게 이 설계의 요점이다.
- **learnset.** op.gg 기술 표에는 "어떤 포켓몬이 이 기술을 배우는지"가 없다.
  파티 빌더(Phase 5)에서 별도 출처가 필요하다.
- **부가효과의 기계적 해석.** 한글 설명문은 수집하지 않았다. 확률·랭크 변화를
  엔진이 쓰려면 별도 작업이 필요하다.
- **플래그 2개의 영문 이름.** '압박'·'상승'은 본가에 대응하는 이름 붙은 플래그가 없어
  이 프로젝트가 키를 정해야 했다. 즉 **데이터에 해석이 끼어든 유일한 지점**이다.
  `_meta.flags_named_by_us`에 근거와 함께 남겼다.
  - `minimize_boosted`('압박')는 설명문에 효과가 명시돼 있고 사용자 확인을 받았다.
  - `rises`('상승')는 **기계적 공통점이 없다**는 것이 확인됐다(멤버가 세 갈래).
    처음 붙인 `airborne`은 없는 공통 성질을 주장하는 이름이어서 바꿨다.
    그룹으로는 쓸 수 없고, 실제 성질은 기술 단위로 모델링해야 한다.

## 되돌리는 조건

- **챔피언스 공식 또는 준공식 기술 데이터 API가 생기면** 즉시 그쪽으로 옮긴다.
  이 결정은 "그런 게 없다"는 사실 위에 서 있다.
- **op.gg가 입장을 바꾸거나 차단하면** D안(수동 큐레이션)으로 내려간다.
  파서를 우회하거나 User-Agent를 위장하지 않는다. 헬프센터 문서는 갱신되므로
  생성기를 돌릴 때마다 정책 페이지를 같이 확인한다.
- **수익화를 검토하는 시점에 이 ADR을 먼저 다시 연다.** 근거가 "출처를 명시하지 않은
  상업적 사용이 아니다"에 서 있어서, 유료화·광고·후원 중 어느 쪽이든 전제가 깨진다.
  그때는 op.gg에 직접 문의해 허가를 받거나 D안으로 옮긴다.
- **요청량이 늘어나면** (예: 레귤레이션마다 자동 재생성) "과도한 요청" 조건에 닿는다.
  생성기를 스케줄러에 올리려는 생각이 들면 그 순간 재검토한다.
- **교차검증 출처가 패치를 따라잡으면** (champions-helper가 갱신되는 등) 주 출처를
  재평가한다. 두 출처가 모두 최신이면 단일 출처 위험이 사라진다.
- **`EXPECTED_*_DIFFS` 화이트리스트가 30건을 넘으면** 두 출처가 너무 벌어진 것이므로
  champions-helper를 교차검증에서 내리고 다른 출처를 찾는다.
- 챔피언스가 PP 체계를 다시 바꿔 `VALID_PP`가 깨지면 그 자체로 생성이 멈춘다.
  그때 본가와의 관계를 다시 조사한다.
